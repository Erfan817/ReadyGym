# 训练实际记录沿用与恢复回访（0.8.13）

用户于 2026-11-02 要求：训练页重量、次数沿用上次；取消每次结束后立即询问身体情况，选择每完成 3 次训练回访。

## 训练输入

- 同动作按 `setIndex` 匹配最近一次已结束训练里的已完成组，带入实际重量、次数和秒数。未勾选的组不作为实际记录，新增或无历史的组使用计划值；不会自动勾选完成。
- 兼容中间漏做一组的稀疏记录，“上次”列与输入匹配同一组号。
- 重启、跨训练日、只修改说明或无关动作导致的计划升级仍可沿用。用户明确确认新的负重、次数范围或计时时长时，按新计划执行；移除后重新加入的动作从新计划起步。
- 不修改归档计划、历史实际记录、当前版本、训练轮换和当天完成门禁。

## 回访节奏

- 每次结束仅展示已保存的训练总结与勋章，点“完成”返回首页；可主动点“现在有不适，主动反馈”。
- 自上次反馈或跳过后，累计 3 次已结束且至少完成一组的训练，并过了最近一次训练结束的本地日期，首页才出现恢复卡片。没有定时通知，不打断训练，不以是否回访限制开始训练。
- 跳过本轮后，再完成 3 次训练进入下一轮；未处理的提醒保留。首页持续提供主动反馈入口。
- 旧版已经保存反馈的训练不重新计入待回访次数。计数检查点用独立 SharedPreferences 持久化，旧训练和反馈仍在 Room。
- 回访询问最近几次训练的整体负担、现在的不适、最近 3 次已练动作的难度和备注，保留“只保存反馈”与明确确认后采用计划的流程。
- 反馈 JSON 增加可选 `reportedAtMillis`，区分训练结束与回访时间；兼容缺失该字段的旧数据。模型提示明确延迟酸痛不能直接归因最近单个动作，不再声称“我刚练完”。

肌肉延迟酸痛可能在训练后一天或更晚出现，没有酸痛不代表训练无效；训练时也可能立即发生疼痛，关节刺痛、麻木等仍应及时停止相关动作，必要时就医。

## 验证范围

新增核心规则、实际存储和 Compose 交互回归，覆盖稀疏组号、重量/次数/秒数、计划变更、移除重加、回访计数/本地日期/跳过/持久化、延迟反馈时间和训练总结分流。发布证据见 `releases/ReadyGym-0.8.13-validation.json`，界面截图见 `screenshots/v0.8.13/`。不修改数据库版本或表结构。
