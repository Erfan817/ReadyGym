# Ready Gym · 底部导航与三页改版（v0.5 设计说明）

## 北极星

> 打开 App 三秒内知道"今天练什么、从哪里开始"；所有解释性文字退到主操作之后。

## 用户与设备

- 想增肌/保持健康、每周练 3–4 次的成年人，手机上单手操作，常在地铁和健身房之间切换。
- 主视口：411×868dp 手机竖屏；同时校验 360dp 小屏与 800dp 宽的平板/横屏。

## 本次要解决的三件事

1. **首页 = AI 教练的入口。** 原来的"教练"是一个 tab 里的整屏聊天，用户在字里行间找入口；现在首页是一张教练卡（头像、一句当前状态、一个主操作），点进去才是完整对话。
2. **动作库 → 我的（用户资料）。** 第五个位置从"动作库"换成"我的"：档案、当前计划、勋章、排行榜集中在这里。
3. **统计按参考图重做，原有日历下移。** 顶部 2×2 指标卡 → 近 12 个月活动热力 → 肌群平衡（本周/30d/90d/全部）→ 原来的月历与当日训练记录。

## 视觉基线（沿用现有 SunnyTheme，不另造系统）

| Token | 值 | 用途 |
| --- | --- | --- |
| Background | `#F3F2F7` | 页面底色（参考图实测同值） |
| Surface | `#FFFFFF` | 卡片、底部导航 |
| Accent | `#34C85A` | 主行动、训练日图标块、中间圆形开始 |

| AccentWash | `#E8F8ED` | 次级绿色按钮底、选中行 |
| Text / MutedText | `#111114` / `#63636A` | 标题 / 说明 |
| 圆角 | 6 / 10 / 14 / 18 / 22 dp | 沿用 GymShapes |
| 间距 | 4 / 8 / 12 / 16 / 20 / 28 dp | 沿用 GymSpacing |

参考图（`refs/start-training.jpg`、`refs/stats.jpg`）实测：页面底 `#F3F2F7`、卡片纯白、唯一饱和色绿 `#34C85A`、左右留白 16–20dp、训练日行高 60dp、行距 8dp、指标卡 78dp 高、双列间距 12dp。与现有 token 完全一致，因此这次只重排结构，不换配色。

## 布局骨架

- **底部导航**：白底 + 1dp 顶部发丝线；四个 tab（图标 24dp + 11sp 标签），中间"开始"是一个 52dp 圆形，向上探出导航条约 14dp。选中 tab 用墨色加粗；中间圆未选中时是浅绿底 + 深绿三角，选中时反过来——因为这个圆没有下方标签，只能自己说明状态。
- **首页**：时段问候 + 教练卡（头像、连接状态、一句基于真实档案的现状、整卡可点的主按钮）→ "现在的状态"三行（档案 / 当前计划 / 最近一次）→ 一句 AI 边界说明。
- **开始**：32sp 标题 + 一句当日判断；今天/其他训练日分组；每行 = 44dp 绿色圆角图标块 + 训练日标题 + "N 个动作 · N 组" + 右侧胶囊（今天为实绿，其余浅绿）。行高 60dp，行距 8dp。图标按训练日名称里的关键词取（推/拉/腿）。
- **统计**：标题 + 2×2 指标卡（84dp 高，12dp 间距）；"活动"卡片含 时间/总量 分段控件与**按卡片宽度铺满**的热力网格；"肌群平衡"卡片含四档日期范围、周切换、横向条形与"没练到"清单；最后是原来的训练日历。
- **我的**：身份卡（昵称 + 目标 + 三个数字 + 改名）→ 训练档案 → 当前计划 → 本周排行榜（需点开才上传）→ 勋章进度 → 账号 → 说明。

## 关键状态

- 无档案：首页与"开始"都指向建档，不显示空计划。
- 有档案无计划：首页说"要我现在排一份吗"，「开始」引导去「计划」。
- 有进行中的训练：首页副标题、"开始"页的首行与胶囊都写"继续"。
- 今天不是计划训练日：标题说"今天不是计划里的训练日。想练也可以，身体说了算。"，且不再把下一个训练日伪装成"今天"。
- 无训练记录：统计指标为 0，热力网格全灰但今天仍有描边环，肌群卡显示空态文案。
- 服务未配置/未同意 AI：首页教练卡显示连接状态，主操作进入对话后仍先要知情同意。

## 动效（三处基本动效 + 一处巧思）

1. **主操作反馈**：中间"开始"按钮按下缩到 0.94 再回弹，落到"开始"页；训练日行整行可点，胶囊只做视觉提示。
2. **状态切换的来路**：分段控件（时间/总量、本周/30d/90d/全部）用同一块底板移动到新位置，并同时改变字重与颜色，色弱下仍可读。
3. **首次入场**：统计的 4 张指标卡按 40ms 间隔、12dp 上移依次出现，只播一次。
4. **巧思**：热力网格里"今天"那一格带绿色描边环，所以即使一格数据都没有，用户也能读出"现在"在网格的哪个位置。

所有时长与曲线来自 `Motion.kt`，`reduceMotion` 下直接到位。

## 与参考图的有意偏离

| 参考图 | 实现 | 理由 |
| --- | --- | --- |
| 第 5 个 tab「动作库」 | 「我的」 | 用户明确要求把动作库位置改成用户资料 |
| Push Day / Pull Day / Leg Day | 计划里的中文训练日标题 | 数据里就是中文标题，另外造一套英文名会和「计划」页对不上 |
| 「自由训练（边练边选）」 | 未做 | 没有"不按计划的自由会话"数据模型，做出来是点了没反应的死控件 |
| 「体重 30 天」指标 | 「本周 N/计划天数」 | App 没有体重记录入口，只能永远显示"—" |
| 「疲劳 / 力量」两个 tab | 只保留肌群平衡 | 没有疲劳与力量数据，不用空图冒充 |
| 一年 53 列热力网格 | 按卡片宽度铺满（约 5 个月） | 53 列在手机上必然要横向滚动，滚起来左右都是半列残块；铺满后网格永远是整列，标题也如实写"近 N 个月" |

## 两轮独立评审与处理

派了两个没有本项目上下文的评审者：一个看视觉层级与工艺兼可用性，一个拿参考图逐像素核对（Pillow 亚像素量边，圆角用圆弧最小二乘拟合）。

**还原度评审的结论：结构全对，尺度整体偏大 10–15%，还原度 65–70%。** 已按它的数值改：

| 项 | 参考 | 改前 | 改后 |
| --- | --- | --- | --- |
| 训练日左侧图标块 | 29dp / 圆角 7dp | 44dp / 14dp | **29dp / 7dp** |
| 训练日右侧胶囊 | 高 21dp / 内距 8dp | 高 37.7dp / 内距 14.5dp | **高 ~21dp / 内距 8dp** |
| 训练日纵向间距 | 8dp | 16dp | **12dp**（配套 block 间距） |
| 页面标题 | 28.9sp | 32.4sp | **29sp** |
| 分区小标题 | 13sp | 15.4sp | **13sp** |
| 指标卡高度 / 内距 | 78dp / 15.4dp | 84dp / 18.7dp | **78dp / 15dp** |
| 指标卡双列间距 | 10dp | 12.2dp | **10dp** |
| 分段控件高 / 滑块高 | 33.9 / 29.9dp | 40 / 36.9dp | **34 / 30dp** |
| 热力图列数 | 固定 21 列 | 随屏宽 23–24 列 | **固定 21 列，方块随宽度缩放** |
| 卡片圆角一致性 | 全部 ~14dp | 统计页 18dp 与 22dp 并存 | **统一 18dp（Panel）/ 14dp（行）** |

**视觉评审的结论：已成系统，但尺度没收干净、状态分不清、统计页工艺不够细。** 已处理：

- 热力图空格对比度 1.18:1 → 加深底色并加 1dp 描边；图例色块 3.8dp → 10dp、标签 11sp→12sp 并改用 `MutedText`；
- 今日格原本"绿底 + 深绿环"与已打卡格难分 → 改为**浅底 + 深色环**，语义只挂在环上；
- "近 4 个月"与 5 个月份标签矛盾 → 改成按 30.44 天四舍五入，标题与坐标轴一致；
- 指标卡顺序 → 改为 **本周完成 → 连续周数 → 本月 → 累计**，把最该看的放第一格；
- 计划页"第 1 天"和"第 3 天"同时染绿（一个表今天、一个表展开）→ 只染今天，展开用正文体量表达；行内"开始"从 68.5dp 收到 40dp；
- 底部导航发丝线在圆形按钮处断开；导航本体压到 64dp 量级；
- 休息日不再把"下一个训练日"伪装成"今天"，改标"下一次"，给出该练哪一天的答案；
- 肌群卡左右箭头统一 `MutedText`，禁用才降透明度。

**未采纳 / 保留**：

1. 评审建议把首页右上角换成用户头像、只保留教练插画一次——**采纳方向但单独排期**：用户头像资源还没做，临时用线条小人会在首页这张最重要的卡上降低完成度，所以这一轮保持现状并记在这里。
2. 评审建议删除「首次使用需要你知情同意」等 13 处文案——**部分采纳**：AI 知情同意入口不能删（这是合规必需，且删了就找不到同意入口），其余已在本次收紧空间时一并改短。
3. Emoji 勋章（⭐🎉🏅）与线稿图标混排——**未改**：勋章体系用的是 emoji 作为可读的成就符号，换成线稿需要重画 11 个图标，超出这次范围。

## 这次不做

- "自由训练（边练边选）"：现有数据模型里没有"不按计划自由开练"的会话类型，做出来只能是一个点了没反应的死控件，因此这次不放；需要先有 `WorkoutSession` 的自由模式。
- 体重曲线：没有体重记录入口，所以不用这个指标卡位，改成"本周完成/计划天数"。
- 疲劳、力量两种统计：没有对应数据。
