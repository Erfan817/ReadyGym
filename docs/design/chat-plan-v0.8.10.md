# v0.8.10：即时发送气泡与聊天调整整周计划

用户于 2026-10-28 提供两张截图：发送后文字仍留在输入框直到回复；教练只能改档案，无法实际替换没有器械或不想做的动作。

## 行为

点发送立即显示用户气泡与“已发送”，输入框清空；模型思考只显示回复提示。失败显示原气泡重试操作，不添加重复消息，也不覆盖之后的新草稿。

已有计划时，教练每轮读取当前整周安排及按档案筛选的动作库，支持动作替换、具体器械不足、组次重量及整周动作结构调整。给1至3套选项；点击查看会展示逐项变化及完整训练日，必须再点“确认采用这套调整”才保存。未确认或选择“先不改”不会写数据库。修改训练日数量/个人档案继续使用原档案确认流程。

## 契约及保存

仍只有 collecting / ready / blocked 三种状态。collecting 的可选 plan_options 每项有 title/detail，并提供完整 days 或 replacements[{day,from,to}]，两者互斥。ConversationPlanContract 校验动作、器械、经验、组次、有限重量、完整训练日和实际变化；第一次无效可带错误反馈纠正一次，失败请求和纠错内容不提交到聊天历史。

用户选择的方案带原始计划及档案快照。事务内重新比较完整当前计划/档案，重新执行安全校验后追加计划版本。保存完成且新计划可读取后才显示成功；陈旧草稿、连点、冲突草稿不会覆盖新计划。所有明确安全路线优先 blocked，即使模型同时错误附带可选方案也不能确认。

聊天调整继承原轮换基线；不改已结束记录，不重置进行中的训练，也不绕过当天已完成的限制。换动作后重量清空，避免继承另一动作的负重。历史计划中不符合当前筛选的动作必须在每套方案中一并修复并说明，旧徒手动作错误负重只在新草稿中清除；旧版本原文保留。

Room 保持版本2，无表迁移。新核心对象无反射序列化依赖，保留已有 kotlinx-serialization keep 规则。
